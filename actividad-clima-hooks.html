Actividad: la app del clima con hooks propios

Vas a construir un buscador de ciudades que muestra el clima actual y el de los próximos siete días, usando la API de Open-Meteo. Todo en un repositorio de GitHub y en Codespaces, sin instalar nada en el computador.

Entrega en grupo. Un commit por paso, con un mensaje que diga qué se hizo. En el historial del repositorio deben aparecer commits de todos los integrantes: repártanse los pasos para que cada uno haga al menos uno.

Paso 0 · El repositorio y el codespace

Una persona del grupo hace esto; los demás lo siguen en su pantalla.

  1. En github.com/new crea un repositorio público llamado clima-react. Marca la casilla para agregar un README.
  2. En la página del repositorio: botón verde Code → pestaña Codespaces → Create codespace on main. La primera vez tarda uno o dos minutos. Se abre VS Code en el navegador.
  3. En la terminal de abajo, crea el proyecto en la carpeta actual: 
    npm create vite@latest . -- --template react --overwrite --no-interactive
npm install
npm run dev

    --overwrite reemplaza el README, pero no toca la carpeta .git: el repositorio sigue conectado.

  4. Aparece un aviso de que la aplicación corre en el puerto 5173. Pulsa Open in Browser. Si el aviso se cerró, abre la pestaña Ports junto a la terminal y haz clic en el ícono del globo del puerto 5173.
  5. Borra el contenido de ejemplo de src/App.jsx (deja una función App con un título «Clima») y vacía src/App.css.
  6. Abre una segunda terminal (el botón +) para no detener el servidor, y guarda el primer commit: 
    git add .
git commit -m "Proyecto creado con Vite"
git push
  7. Ahora que el repositorio tiene código, agrega a tus compañeros: Settings → Collaborators → Add people, con su usuario de GitHub. No lo hagas antes del primer push: con el repositorio vacío, la invitación puede no llegar.
  8. Cada compañero acepta la invitación entrando a https://github.com/USUARIO/clima-react/invitations (cambia USUARIO por el de quien creó el repositorio). No esperen el correo: a veces llega tarde o cae en spam.

Quedó bien si: en la pestaña del navegador ves el título «Clima», y en GitHub el repositorio ya tiene package.json y la carpeta src.

Para trabajar los tres: cada compañero abre su propio codespace sobre el mismo repositorio (Code → Codespaces → Create codespace on main), corre npm install y npm run dev, y trabaja el paso que le tocó. Antes de empezar, siempre git pull para traer lo último; al terminar, git add, git commit y git push. Si el push dice que hay cambios nuevos en el remoto, haz git pull y vuelve a intentar.

En Codespaces, Git ya viene configurado con la cuenta de GitHub de quien abrió el codespace, así que cada commit queda a nombre de quien lo hizo. Por eso cada uno trabaja en su propio codespace y no en el de un compañero.

Paso 1 · Buscar ciudades (unos 20 minutos)

Un campo de texto controlado. Cuando tenga al menos tres letras, la app busca ciudades con ese nombre y las muestra en una lista: nombre, departamento y país. Muestra también «Buscando…» mientras llega la respuesta, el error si falla y «Sin resultados» si no hay coincidencias.

La URL para buscar es esta (cambia Cucuta por lo que se escribió, pasado por encodeURIComponent):

https://geocoding-api.open-meteo.com/v1/search?name=Cucuta&count=5&language=es

Pégala en una pestaña nueva del navegador para ver qué devuelve. Cada ciudad trae id, name, admin1 (el departamento), country, latitude y longitude.

Pista: por ahora hazlo como en la clase anterior, con useEffect, AbortController y los tres estados, todo dentro de App. Ojo: cuando no hay coincidencias, la respuesta llega con código 200 pero sin la propiedad results. Prueba con «zzzqqq».

Quedó bien si: escribes «Pamplona» y aparecen varias, entre ellas la de Norte de Santander; con «zzzqqq» aparece «Sin resultados»; con una o dos letras no se hace ninguna petición (revísalo en la pestaña Network).

Paso 2 · Tu primer hook: useFetch (unos 20 minutos)

Saca toda la lógica de la petición a un archivo src/hooks/useFetch.js. El hook recibe una URL y devuelve un objeto con tres propiedades: datos, cargando y error. Si la URL es null, no pide nada.

// así se debe poder usar en App.jsx
const url = texto.length >= 3 ? `https://...search?name=${encodeURIComponent(texto)}&count=5&language=es` : null;
const ciudades = useFetch(url);

// ciudades.datos, ciudades.cargando, ciudades.error

Pista: copia el useState y el useEffect de App dentro de una función export function useFetch(url), cambia la dependencia por [url] y al principio del efecto pon if (!url) return;. Fíjate en la regla de los hooks: el if va dentro del hook, no alrededor de useFetch.

Quedó bien si: la app funciona exactamente igual que en el paso 1, y App.jsx ya no tiene ningún fetch ni useEffect para buscar ciudades.

Paso 3 · El pronóstico, con el mismo hook (unos 20 minutos)

Al hacer clic en una ciudad de la lista, se guarda en el estado y aparece debajo su clima actual (temperatura, descripción y viento) y los siete días siguientes con mínima, máxima y descripción.

https://api.open-meteo.com/v1/forecast?latitude=7.9&longitude=-72.5&current=temperature_2m,weather_code,wind_speed_10m&daily=temperature_2m_max,temperature_2m_min,weather_code&timezone=auto

La respuesta trae current con el clima de ahora y daily con arrays paralelos: daily.time[0], daily.temperature_2m_max[0] y daily.temperature_2m_min[0] son del mismo día. El clima viene como un número (weather_code). Copia esta función en src/clima.js para convertirlo en texto:

export function describirClima(codigo) {
  if (codigo === 0) return "☀️ Despejado";
  if (codigo <= 3) return "⛅ Parcialmente nublado";
  if (codigo <= 48) return "🌫️ Niebla";
  if (codigo <= 57) return "🌦️ Llovizna";
  if (codigo <= 67) return "🌧️ Lluvia";
  if (codigo <= 77) return "❄️ Nieve";
  if (codigo <= 82) return "🌧️ Chubascos";
  return "⛈️ Tormenta";
}

Pista: no escribas otro fetch. Llama useFetch una segunda vez con la URL del pronóstico, armada con la latitud y la longitud de la ciudad elegida, o null si todavía no se ha elegido ninguna.

Quedó bien si: eliges Cúcuta y ves su clima; eliges otra ciudad y el pronóstico cambia; y en tu código hay dos llamadas a useFetch y un solo fetch en todo el proyecto.

Paso 4 · Resumen de la semana con useMemo (unos 15 minutos)

Encima de los siete días, una línea que diga la máxima y la mínima de la semana y cuál es el día más caluroso.

Pista: calcula el resumen dentro de useMemo, con los datos del pronóstico como dependencia. Math.max(...array) da el mayor de un array, e indexOf te dice en qué posición está, que es la misma posición en daily.time. Pon un console.log("calculando resumen") dentro del useMemo.

Quedó bien si: el resumen es correcto y, con una ciudad ya elegida, escribir en el buscador no imprime «calculando resumen» en la consola. Solo se imprime cuando cambia la ciudad.

Paso 5 · El foco con useRef (unos 10 minutos)

Al abrir la app, el cursor ya está en el campo de búsqueda, sin hacer clic. Junto al campo, un botón «Limpiar» que borra el texto, quita la ciudad elegida y vuelve a poner el cursor en el campo.

Pista: const entrada = useRef(null), <input ref={entrada} ... /> y entrada.current.focus(). Para el foco inicial, un efecto con [].

Quedó bien si: recargas la página y puedes escribir de una; pulsas Limpiar y también.

Paso 6 · Opcional: no buscar con cada tecla

Al escribir «Bucaramanga» rápido, hoy salen nueve peticiones, una por cada letra desde la tercera. Haz que la búsqueda espere a que pasen 400 milisegundos sin escribir antes de pedir.

Pista: otro hook propio, useDebounce(valor, ms), que devuelve el valor solo cuando lleva ms milisegundos sin cambiar. Por dentro es un useEffect con un setTimeout y su limpieza con clearTimeout. Busca con el valor que devuelve, no con el texto del campo.

Quedó bien si: en la pestaña Network, escribir «Bucaramanga» de corrido genera una sola petición.

Entrega

Sube a nplad el enlace del repositorio, por ejemplo https://github.com/usuario/clima-react. Antes de enviarlo, ábrelo en una ventana de incógnito para comprobar que es público y que tiene el último commit.

Al terminar, detén el codespace: entra a github.com/codespaces, abre el menú de tres puntos de tu codespace y elige Stop codespace. Las cuentas gratuitas tienen un límite de horas al mes, y un codespace abierto sigue gastando hasta que se apague solo por inactividad.
